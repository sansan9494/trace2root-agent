# OnCall 工具安全与人工审批 Runbook

> 本文件是项目维护的中文策略，参考 NIST SP 800-61 Rev.3 的事件响应建议及 NIST SP 800-53 Rev.5 的配置变更控制原则整理，不是 NIST 官方中文译本。
>
> 来源：https://doi.org/10.6028/NIST.SP.800-61r3 、https://doi.org/10.6028/NIST.SP.800-53r5

## 风险等级

- L0：无副作用的本地计算，例如读取当前时间、格式转换。可以自动执行。
- L1：只读查询，例如读取告警、指标、日志、服务状态和知识库。可以自动执行，但必须限制时间窗口、返回条数并脱敏。
- L2：低影响且可追踪的外部动作，例如向明确 allowlist 的 Mock 通知渠道发送消息。执行前校验目标并记录审计。
- L3：可能改变服务状态的动作，例如生产重启、回滚、扩缩容、流量切换、修改配置。必须人工审批，默认不得执行。
- L4：高破坏性或敏感动作，例如删除生产数据、清空队列、关闭审计、导出凭据、修改密钥或绕过访问控制。首版 Agent 禁止执行，审批也不能解除禁止。

## L3 审批前必须具备的证据

审批请求必须包含告警对象和环境、候选根因、支持证据、目标工具及完整参数、预期影响、回退方案、操作人、审批人和有效期限。证据不足、目标不明确、参数超出允许范围或没有回退方案时应拒绝审批并继续只读调查。

根因结论至少应由两个独立信号交叉验证，例如指标异常加对应错误日志，或者部署时间加 Trace 中的首个失败服务。只有单一告警或单条日志时，应降低置信度，不能直接触发写操作。

## 审批状态机

1. Agent 完成只读调查并提出 L3 建议。
2. 工具注册表拦截调用，创建 `waiting_approval` 请求，不执行目标操作。
3. 审批人核对证据、参数、影响和回退方案，可以批准或拒绝。
4. 审批必须绑定 task_id、工具名和参数摘要；超时或参数变化后原审批失效。
5. 批准后仍需再次进行参数校验和权限校验，并记录开始时间、结束时间、结果和 trace_id。
6. 本项目处于安全演示模式，即使批准 `restart_service` 也只返回 `executed=false`，不会触碰真实环境。

## 紧急事件与失败处理

紧急程度不能自动绕过 L3/L4 控制。如果审批人不可用，应升级到预先定义的值班负责人；没有授权时继续执行只读调查、影响隔离建议和通知。工具超时、MCP 断开或数据源失败必须写入报告，不得将“未查询到数据”解释为“系统正常”。

## 审计与敏感信息

所有工具调用记录工具名、校验后的参数、风险等级、调用来源、结果、耗时和 trace_id。日志输出必须遮盖 Token、API Key、密码、手机号和邮箱。审批记录不得包含明文凭据。任何关闭审计、扩大权限或读取 Secret 的请求均按 L4 禁止处理。
